Forge refuses three setups that used to resolve and then fail at compile or ROMS start-up, or start a MARBL run with no plankton.
- Under MARBL, an initial-conditions or boundary BGC source set in which no source provides ``CHL`` or none provides ``Fe`` (for example ESPER only, GLODAP or WOA_BGC only, or a ``constants`` source without them). roms-tools derives the phytoplankton and zooplankton tracers from ``CHL`` and the iron ligand from ``Fe``, and set them to zero without those. Complete the set by keeping a UNIFIED item with ``use_vars`` including ``CHL`` and ``Fe`` beside the other sources, as the bundled ``glorys-era5-esper`` and ``glorys-era5-glodap-woa`` ForcingSpecs do, or by adding ``CHL`` and ``Fe`` values to a ``constants`` source. A CESM_REGRIDDED source, which supplies those tracers directly, is accepted.
- ``cppdefs.marbl: true`` set as an override without ``bgc_mode: marbl``, which built no MARBL library. Set ``bgc_mode: marbl`` instead.
- Open boundaries with no ``forcing.boundary`` block on a domain that is not a nested child. Add a boundary block or close those sides in the domain's ``open_boundaries``; a child still takes its boundary from its parent.

Describe a cluster C-Star does not know in a system file of your own: a ``systems/<name>.yaml`` file under your catalog (``~/cstar/catalog`` by default) or under a group's catalog listed in ``CSTAR_CATALOG`` is used like a bundled system, and one with a bundled system's name replaces it, with a warning. See "Describe your cluster" in the deployments docs.
- New ``cstar system`` commands: ``list`` shows every system C-Star can see and which file it uses, ``show NAME`` prints a system's file to start your own from, ``template`` prints a commented blank one, ``check [NAME|PATH]`` tests a file on the machine it describes, and ``add PATH`` copies a checked file into your catalog or, with ``--catalog``, a group's.
- ``cstar init --system-file PATH`` sets C-Star up with a system file and puts the file where C-Star finds it; the System section of ``cstar init`` also accepts the path of a system file.
- A system file C-Star cannot use (invalid YAML or schema, a name that does not match the file name, or writable by every user) is skipped with a warning that names it and why; ``CSTAR_SYSTEM`` naming such a file is an error that says why.
- ``cstar env show`` names the system file in use when it is not a bundled one.

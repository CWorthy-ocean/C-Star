.. _0.19.0:

0.19.0
------

Breaking Changes
~~~~~~~~~~~~~~~~

- A workplan's ``slurm`` settings (a step's ``compute_overrides.slurm`` or the workplan's ``compute_environment.slurm``) now reject unknown keys instead of ignoring them; remove or correct the key the error names. (`#885 <https://github.com/CWorthy-ocean/C-Star/pull/885>`_)
- Branch pins select the newest tier in both Forge and ``ucla_roms``, so a run pinned to a ucla-roms branch without ucla-roms #413 stops on the new keys; a commit-hash pin resolves to its nearest release tag and keeps that release's tier. (`#896 <https://github.com/CWorthy-ocean/C-Star/pull/896>`_)
- New namelist tier for ucla-roms >= 0.14.0 that adds ``wrt_avg_temp``/``wrt_avg_salt``; earlier releases stop on unknown namelist keys, so they keep the 0.13 tier and Forge rejects either key switched on there with an error naming 0.14.0. (`#896 <https://github.com/CWorthy-ocean/C-Star/pull/896>`_)
- On ucla-roms 0.14.0 and later, a MARBL run needs BGC sources for its boundary forcing and initial conditions (ucla-roms #421): a physics-only ForcingSpec such as ``glorys-era5-physics`` now needs ``bgc_mode: none``. (`#896 <https://github.com/CWorthy-ocean/C-Star/pull/896>`_)
- C-Star now requires roms-tools 5.4.0 or later (``roms-tools>=5.4.0,<6``); upgrade roms-tools in your environment along with C-Star. (`#897 <https://github.com/CWorthy-ocean/C-Star/pull/897>`_)
- On Bouchet, C-Star builds with the ``gompi-2024a`` toolchain in place of ``gompi-2022b``: rebuild ROMS, MARBL and ParallelIO builds made there before this release. (`#905 <https://github.com/CWorthy-ocean/C-Star/pull/905>`_)
- Forge now refuses surface or boundary forcing whose records do not span the run window, naming the file, the time variable and its first or last record; before, it wrote truncated forcing and ROMS stopped once its clock passed the last record, possibly hours into the run. (`#926 <https://github.com/CWorthy-ocean/C-Star/pull/926>`_)

  - ROMS needs a record at or before ``start_date`` and one at or after ``end_date`` for every forcing variable; a climatology is exempt. Stage source data that covers the window, or shorten it.
  - The check also runs on files a rerun reuses, so a window extended since the inputs were generated is refused until they are regenerated with ``--clobber``.
  - Initial conditions that would start the model at another time than ``start_date`` are refused the same way, including a file written with flexible start time by an earlier release.

- Forge refuses a CDR forcing that does not fit the run or the grid, which it used to generate without a message. (`#927 <https://github.com/CWorthy-ocean/C-Star/pull/927>`_)

  - A CDR window (``cdr_forcing`` ``start_time``/``end_time``) that does not cover the run, or a release whose ``times`` all fall outside the run, is refused when the blueprint is built or processed.
  - A release outside the domain, or so far below the seafloor that its vertical profile is zero at every level, is refused before any input is generated; ROMS used to move the first to the nearest cell and deliver none of the second.
  - ``cdr_frc.time_interpolation`` set against the releases' ``time_interpolation`` is refused, including in a blueprint saved before this version whose CDR releases set ``time_interpolation: true``; set the two to match.

- A ``nest-from`` or ``carbonate-sensitivity-from`` directive now stops the step before ROMS starts when the files it gathers leave a gap in time, or do not reach back to the step's ``start_date`` and on to its ``end_date``; before, ROMS interpolated linearly across a missing segment with no message, and a source that ended early failed only when the model time reached its end. (`#929 <https://github.com/CWorthy-ocean/C-Star/pull/929>`_)

  - List every segment of the source, separated by ``;``: ``step: parent_1;parent_2;parent_3``, or ``path:`` with one output directory per segment. The error names the files on both sides of each gap.
  - A gap is a stretch more than twice as long as the spacing of the records around it. Records at the same time where two runs meet, and an output period that changes from one segment to the next, are not gaps.

- Forge refuses, when a blueprint is resolved or validated and before any input is generated, settings that used to be ignored or to stop the run only after the ROMS build; the wizard's settings check lists them too. (`#930 <https://github.com/CWorthy-ocean/C-Star/pull/930>`_)

  - An unknown section or key in ``model_settings``, overrides or OutputSpecs, such as ``botom_drag``, ``ocean_vars.wrt_fiel_his`` or ``cppdefs.diagnostic``, is refused with the nearest valid name. A key the pinned ucla-roms release does not have still gets its message naming the release that adds it.
  - ``pipe_frc.pipe_source: true`` is refused: Forge writes no pipe forcing, so ROMS stopped at initialisation.
  - ``n_procs_x`` or ``n_procs_y`` that leave a tile with no grid points (16 × 16 tiles on an 8 × 8 grid, or 9 tiles across 10 points) are refused with the largest count that works.
  - ``run.model_reference_date`` with a time of day is refused when the blueprint loads; use midnight. ROMS refused such a run after the build.

- Forge and ``ucla_roms`` blueprints whose output periods or MARBL step ucla-roms refuses at start-up are now refused before inputs are generated or ROMS is compiled, and a run that would write no output stops before it starts. (`#931 <https://github.com/CWorthy-ocean/C-Star/pull/931>`_)

  - An enabled history, average or BGC output period (``output_period_his``, ``output_period_avg``, ``output_period_bgc_his``, ``output_period_bgc_avg``, ``output_period_bgc_his_dia``, ``output_period_bgc_avg_dia``) must be a whole multiple of ``dt``. For example, hourly output is refused with a ``dt`` of 7200 s or 960 s.
  - With MARBL, a MARBL step above 10,800 s is refused: any ``dt`` above 10,800 s, or a ``marbl_timestep`` that rounds down to more than 10,800 s.
  - A ``ucla_roms`` run in which no output stream writes (for example, a one-day run with weekly or monthly restarts and nothing else enabled) is refused before it starts; when ``time_stepping.ntimes`` is set by a namelist override, this is a warning instead. Forge warns about such a run, since a ``ucla_roms`` step may run only part of its window.
  - Forge and ``ucla_roms`` warn when another stream's period (CDR, CDR-lite, CDR gas exchange, upscaling, nesting extraction, forcing, surface flux and the rest) is not a whole multiple of ``dt``, naming the period ROMS writes it at instead, for example every 3840 s for hourly output with ``dt`` 960 s.
  - A ``ucla_roms`` blueprint's output-stream checks, including the restart-file and MARBL-step averaging checks that used to run only just before launch, now also run during setup, as soon as the namelist is fetched and before the input datasets are staged or ROMS is compiled.

- Forge refuses a MARBL setup whose biogeochemical sources would start the plankton at zero, and two setups that used to fail at compile or ROMS start-up. (`#932 <https://github.com/CWorthy-ocean/C-Star/pull/932>`_)

  - An initial-conditions or boundary BGC source set with no ``CHL`` or no ``Fe`` source (ESPER, GLODAP or WOA_BGC alone) is refused; keep a UNIFIED item supplying ``CHL`` and ``Fe`` as the bundled specs do, or add them to a ``constants`` source.
  - ``cppdefs.marbl: true`` set as an override without ``bgc_mode: marbl`` is refused; set ``bgc_mode: marbl`` instead.
  - Open boundaries with no ``forcing.boundary`` block are refused unless the domain is a nested child; add a boundary block or close those sides.

- Removed: automatic time-splitting and its feature flags ``CSTAR_FF_ORCH_TRX_TIMESPLIT``, ``CSTAR_FF_ORCH_TRX_TIMESPLIT_FREQ`` and ``CSTAR_FF_ORCH_TRX_TIMESPLIT_LONGNAME``; split a run into explicit workplan steps chained with ``continue-from`` (the wizard's "Chunk a run in time" recipe writes them). (`#933 <https://github.com/CWorthy-ocean/C-Star/pull/933>`_)

  - An exported flag has no effect, and the CLI says so: each ``ucla_roms`` step now runs its whole period as one job.

- Forge refuses an override that contradicts a value it derives from the generated inputs, naming the setting, both values and the blueprint field to change instead; before, the override won and the namelist or cppdefs no longer matched the input files. (`#935 <https://github.com/CWorthy-ocean/C-Star/pull/935>`_)

  - The refused overrides are ``blk_frc.interp_frc`` and ``bgc.interp_frc`` (set by each surface item's ``coarse_grid_mode``), ``param.llm``, ``mmm``, ``n``, ``np_xi`` and ``np_eta`` (``domain.grid_kwargs`` and ``domain.partitioning``), ``extract_data.n_chd``, ``theta_s_chd``, ``theta_b_chd`` and ``hc_chd`` (``domain.grid_kwargs_child``) and ``cppdefs.obc_*`` (``domain.open_boundaries``). The wizard can set the two ``interp_frc`` values under Advanced settings; an override equal to the derived value is kept.
  - A parent's ``domain.grid_kwargs_child`` must give the child's ``N``, ``theta_s``, ``theta_b`` and ``hc`` when the blueprint is built; Forge used to fill a missing ``N`` or ``hc`` with values (90 levels, 250 m) that differ from those roms-tools builds the child with (100, 300 m). A saved blueprint without them still loads and runs.

- New namelist tier for ucla-roms >= 0.16.0 that adds ``pio_settings.pio_direct_read``; earlier releases stop on unknown keys in ``&PIO_SETTINGS``, so they keep the 0.15 tier, where Forge drops ``on`` and ``off`` (both read through ParallelIO there) and rejects ``verify`` with an error naming 0.16.0. (`#939 <https://github.com/CWorthy-ocean/C-Star/pull/939>`_)

  - Branch pins select the newest tier in both Forge and ``ucla_roms``, so a ParallelIO run pinned to a ucla-roms branch without ucla-roms #462 stops on the new key; builds without ParallelIO never read the group and still run.
  - A commit-hash pin resolves to its nearest release tag and keeps that release's tier.

Python API Changes
~~~~~~~~~~~~~~~~~~

- Removed with time-splitting: ``RomsTimeSplitter``, ``SplitFrequency``, ``get_time_slices``, ``apply_automatic_overrides``, the transform registry (``TRANSFORMS``, ``register_transform``, ``get_transforms``), ``Transform.is_active`` and ``LiveStep.parent``. (`#933 <https://github.com/CWorthy-ocean/C-Star/pull/933>`_)

  - ``ApplicationDefinition.applicable_transforms`` is no longer read or required; an application that still declares transforms there gets a warning when it registers, and they do not run.

Changes to Output
~~~~~~~~~~~~~~~~~

- Forge names a boundary or surface BGC file whose ``use_vars`` tag would exceed 40 characters ``<source>-<n>vars_<digest>`` (e.g. ``boundary-bgc-unified-23vars_3581d4be.nc``) instead of joining every variable; a domain already generated under the old long name keeps and reuses its file. (`#879 <https://github.com/CWorthy-ocean/C-Star/pull/879>`_)
- Saved forge blueprints leave out ``glorys_layout``, ``constants``, ``esper_method`` and ``esper_equation`` on sources where they are unset, so a source shows only the fields that apply to it; existing files still load and content hashes are unchanged. (`#890 <https://github.com/CWorthy-ocean/C-Star/pull/890>`_)
- ucla-roms 0.14.0 changes results wherever water flows in through an open boundary (ucla-roms #415). (`#896 <https://github.com/CWorthy-ocean/C-Star/pull/896>`_)
- With roms-tools 5.4.0, Forge and ``nest_ic`` write different initial conditions, boundary forcing and surface forcing from an unchanged blueprint. (`#897 <https://github.com/CWorthy-ocean/C-Star/pull/897>`_)

  - Below a source column's bottom, tracers now blend over 25 m into the nearest column with water at that depth instead of copying the bottom value down; ``bottom_fill_blend_m: .inf`` restores the old fill.
  - ERA5 ``qair`` is computed from ERA5's surface pressure instead of a fixed 1010 hPa, which changes it by about 1% over the ocean.
  - ESPER-derived tracers are groomed by default (``groom: false`` turns it off), and ESPER oxygen is floored at 5.0 mmol/m³ instead of 2.0, with no switch.

- ucla-roms 0.15.0 writes different output from an unchanged setup: (`#911 <https://github.com/CWorthy-ocean/C-Star/pull/911>`_)

  - Nested child runs give different results: the boundary data a parent extracts now hold ``u``, ``v`` and the tracers at the time of the record, one parent time step later than before (ucla-roms #435).
  - MARBL diagnostics are written in double precision, which changes them by up to 6e-8 relative (ucla-roms #443).
  - With ``wrt_bgc_his`` off and ``wrt_bgc_avg`` on, each ``_bgc_dia`` file holds ``nrpf_bgc_his_dia`` records instead of one (ucla-roms #437).

- Forge stages the corrected unified BGC climatology as ``BGCdataset_v2_1b.nc``, in which the negative deep-ocean values that interpolation left in the labile DOC, DON and DOP fields are set to zero; the first Forge run after upgrading downloads it again (about 10 GB) into the shared source-data cache. (`#918 <https://github.com/CWorthy-ocean/C-Star/pull/918>`_)

  - A cached ``BGCdataset_v2_1a.nc`` is reported as stale on every staging run until it is deleted; Forge never deletes it.
  - Domains whose initial or boundary BGC came from UNIFIED should be regenerated before a run that will be compared with earlier ones.

- The bundled DomainSpecs ``PAC_2fth_deg``, ``NEP-4th_deg`` and ``GoA-10th_deg`` now have their grid axes swapped, at rotation 0, 0 and -15 instead of -90, -90 and -105: the grid points and cells are the same, but every file made from them is transposed and the processor layout is 8 by 16 instead of 16 by 8. (`#920 <https://github.com/CWorthy-ocean/C-Star/pull/920>`_)

  - Their boundary names now match the compass, and each opens its geographic south edge, all open ocean, which was a closed wall before; ``GoA-10th_deg`` stays closed only on its east edge, which is all land.
  - At the old rotations, roms-tools 5.4.0 and earlier wrote winds and initial and boundary currents reversed in half the cells of ``PAC_2fth_deg`` and ``NEP-4th_deg`` and all of ``GoA-10th_deg`` (CWorthy-ocean/roms-tools#737); at the new rotations no cell is affected.
  - A run made from the old specs cannot be continued from the new ones.

- With flexible start time (``initial_conditions.allow_flex_time``), the initial conditions are now stamped at ``start_date``, so ROMS starts there; before, ROMS started at the source record roms-tools took (up to 24 hours later) while the blueprint, the forcing and the CDR releases kept the requested dates. The record's own time is kept in the file's ``ini_time_source_record`` attribute, and Forge warns when it differs from ``start_date``. (`#926 <https://github.com/CWorthy-ocean/C-Star/pull/926>`_)
- The namelist's ``cdr_time_interpolation`` now follows the CDR releases' ``time_interpolation``, so releases with ``time_interpolation: true`` are interpolated in time, as roms-tools accounts them, instead of held as steps one record late. (`#927 <https://github.com/CWorthy-ocean/C-Star/pull/927>`_)
- Forge derives the time step from the grid unless you set one, and the derived ``dt`` is now the largest divisor of 3600 s at or below the CFL estimate, so a new blueprint can get a different ``dt``. (`#934 <https://github.com/CWorthy-ocean/C-Star/pull/934>`_)

  - The wizard no longer saves 7200 s by default: until you type a time step it shows and saves the derived value, which follows grid edits, and "Use CFL value" (formerly "Compute from CFL") goes back to it.
  - Derived ``dt`` for the bundled domains: GoA-10th_deg 450 s, NEP-4th_deg 1200 s, PAC_2fth_deg 1800 s, ccs-12km 900 s, hvalfjordur-0 180 s, wio-toy and gulf-guinea-toy 3600 s (MARBL stopped at startup with their old values).
  - A DomainSpec saved from the wizard carries ``dt`` only when you set it.

- Forge writes the values it derives from the generated inputs into the namelist and cppdefs even when the saved blueprint's ``model_settings`` holds an older or hand-edited value, so the same blueprint can now render a different namelist. (`#935 <https://github.com/CWorthy-ocean/C-Star/pull/935>`_)

  - With ``coarse_grid_mode: always``, or ``auto`` when roms-tools puts the surface files on the coarse grid, the namelist says ``interp_bulk_frc = .true.`` and ``interp_bgc_frc = .true.``; it used to say ``.false.``, which does not match the files.
  - A parent whose ``grid_kwargs_child`` left out ``N`` or ``hc`` gets the child's ``n_chd`` and ``hc_chd`` from the child grid roms-tools built (100 levels and 300 m by default) instead of 90 and 250 m.
  - A grid size, tile count or open-boundary switch edited in ``model_settings`` (rather than in ``domain``) is replaced by the value from the grid, the partitioning or ``open_boundaries``.

- The default ModelSpec, the wizard default, the bundled domains and the integration pin move to ``roms-marbl-0.16-default`` (ucla-roms 0.16.0), which writes different output from an unchanged setup; ``roms-marbl-0.15-default``, ``roms-marbl-0.14-default`` and ``roms-marbl-0.13-default`` stay for reproducing earlier answers. (`#939 <https://github.com/CWorthy-ocean/C-Star/pull/939>`_)

  - 3-D results change: the predictor step splits the vertical velocity differently (ucla-roms #468), and lateral viscosity, including the sponge's, now acts on the depth-averaged flow, which changes ``ubar``, ``vbar`` and ``zeta`` most in the sponge layer (ucla-roms #473).
  - Each record of the ``_avg`` and ``_bgc_avg`` files averages the model states one step later than before, and these files and ``_bgc_dia_avg`` gain ``avg_begin_time`` and ``avg_end_time``; pair ``_avg`` and ``_bgc_avg`` records by ``avg_end_time`` (ucla-roms #472).
  - ``w`` in history, averages and boundary output includes the water added by point sources, such as CDR releases with ``cdr_volume`` (ucla-roms #470).
  - Parameterized CDR releases spread over several cells (``cdr_hsc`` > 0) can change at the rounding level: their weights no longer depend on the tiling (ucla-roms #470).
  - Builds without ParallelIO write their per-rank output as uncompressed CDF-5 instead of netCDF-4, so those files are larger; joined files are still compressed netCDF-4 (ucla-roms #470).

New features
~~~~~~~~~~~~

- ``nest_ic`` blueprints accept ``bottom_fill_blend_m`` for the child's initial conditions, where the child is deeper than the parent (blueprint schema 1.2.0). (`#877 <https://github.com/CWorthy-ocean/C-Star/pull/877>`_)
- Forge blueprints accept ``bottom_fill_blend_m`` in ``initial_conditions`` and ``boundary``: the depth below a source column's bottom over which tracers blend into the nearest column with water at that depth. (`#877 <https://github.com/CWorthy-ocean/C-Star/pull/877>`_)

  - ``0`` takes the neighbouring column's value at once, ``.inf`` copies the bottom value down, and leaving it unset uses roms-tools' default.
  - The wizard has a "Below-bottom blend depth" box in the initial-conditions and boundary interpolation settings.

- The wizard has a "Groom ESPER tracers" checkbox on the initial-conditions and boundary sections, checked by default. It keeps any hand-written ``groom_settings`` when a blueprint is loaded and saved again with the box checked, and leaves them out while the box is unchecked. (`#878 <https://github.com/CWorthy-ocean/C-Star/pull/878>`_)
- Forge blueprints accept ``groom`` on ``initial_conditions`` and ``boundary``; ``groom: false`` turns off ROMS-Tools' grooming of ESPER-derived tracers, which is on by default. (`#878 <https://github.com/CWorthy-ocean/C-Star/pull/878>`_)

  - On (the default, ROMS-Tools' own) is left out of saved blueprints and the content hash, so existing blueprints keep their hash and an explicit ``groom: true`` hashes the same as leaving it out.

- Forge blueprints accept ``groom_settings`` on ``initial_conditions`` and ``boundary``, overriding ROMS-Tools' grooming thresholds; it is set by hand in the blueprint YAML only. (`#878 <https://github.com/CWorthy-ocean/C-Star/pull/878>`_)

  - Unknown keys or invalid values fail when the blueprint loads, and so does ``groom_settings`` with ``groom: false``, since ROMS-Tools applies the settings only while grooming is on. An empty ``groom_settings`` counts as unset.

- Forge blueprints and ModelSpecs accept ``cppdefs.diagnostics`` to define ``DIAGNOSTICS`` in the generated ``cppdefs.opt``. (`#880 <https://github.com/CWorthy-ocean/C-Star/pull/880>`_)
- The wizard's diagnostics output row has a Diagnostics switch that compiles ucla-roms with ``DIAGNOSTICS``, writing the ``_dia`` file of momentum and tracer term balances. (`#880 <https://github.com/CWorthy-ocean/C-Star/pull/880>`_)

  - Off by default; while it is off, the other diagnostics settings are hidden.
  - The temperature and salinity diagnostics boxes sit in the same row and show only while tracer diagnostics are on.
  - With ParallelIO it needs ucla-roms 0.13.1 or later; Forge refuses diagnostics with ParallelIO on an older release pin, which aborts at the first diagnostics output.
  - Known issue: in ucla-roms 0.16.0 and earlier, tracer diagnostics can corrupt memory and crash a finished run as it shuts down when a tile is three or more grid points wider than it is tall (ucla-roms #476); leave tracer diagnostics off, or set ``n_procs_x`` and ``n_procs_y`` so tiles are about square.

- Workplan steps can run on GPU nodes: ``num_gpus`` (and optionally ``gpus_per_node``) in a step's ``slurm`` settings requests GPUs, and C-Star lays the job out evenly over the nodes. (`#885 <https://github.com/CWorthy-ocean/C-Star/pull/885>`_)

  - A GPU step goes to the system's GPU queue unless ``CSTAR_SLURM_GPU_QUEUE`` names another, and is charged to ``CSTAR_SLURM_GPU_ACCOUNT`` when set, else ``CSTAR_SLURM_ACCOUNT``; ``cstar init`` offers both.
  - On Perlmutter a GPU job needs an account (NERSC policy), so C-Star refuses to compose one without.
  - A step whose application needs a toolchain the system does not have (GPU builds on Anvil) is refused before it is submitted, not after it waits in the queue.

- GPU runs are supported on Perlmutter with roms-marbl-gpu v0.1.3-beta, from its public repository. (`#885 <https://github.com/CWorthy-ocean/C-Star/pull/885>`_)
- New application ``ucla_roms_gpu`` (blueprint schema 1.0.0) runs roms-marbl-gpu on GPU nodes, one GPU per tile, with C-Star building the model from the pinned roms-marbl-gpu release. (`#885 <https://github.com/CWorthy-ocean/C-Star/pull/885>`_)

  - A ``tiling`` block sets the tiles (``n_procs_x``, ``n_procs_y``), the ``nodes`` the job spans and the ``writers_per_node`` output ranks (default 1); C-Star requests ``tiles + writers_per_node x nodes`` MPI tasks.
  - Namelist settings the GPU model would stop on are refused before the build and again before launch: switches for features it lacks, and more forcing files than it reads (64).
  - Forcing that holds surface restoring data is refused once staged, before the build, since the GPU model would ignore it (see Known gaps).
  - A bundled ``wales-toy-gpu`` example blueprint runs a toy domain on one 4-GPU node.
  - roms-marbl-gpu v0.1.3-beta and later are supported; an older pin is refused when the blueprint is checked.

- New command ``cstar run compress <run>`` compresses the netCDF data files of a finished run in place, keeping the variables analyses and later steps need exact. (`#886 <https://github.com/CWorthy-ocean/C-Star/pull/886>`_)

  - For each detected file type it asks: compress it, cast non-protected variables to float32, also quantize them (BitGroom, significant digits), and override the chunk shape.
  - Restart, nesting boundary, carbonate sensitivity (``_cdrgas``) and forge files default to not compressed: other runs read them, and a CPU ROMS build with ParallelIO cannot read netCDF-4 input.
  - Each file is checked against its original (the first and last record of each variable) before it replaces it; originals are kept under ``uncompressed_originals/`` unless you choose to delete them.

- The answers are saved as a ``compress`` blueprint in ``<run>/compress/``, which ``--blueprint`` reuses on another run (asking only about file types it does not match) and ``cstar blueprint run`` runs directly. (`#886 <https://github.com/CWorthy-ocean/C-Star/pull/886>`_)
- ``--submit`` submits the compression as a one-step SLURM workplan, ``--now`` compresses in the current process, and ``--workers N`` sets how many files are compressed at once (the job's cores with ``--submit``). (`#886 <https://github.com/CWorthy-ocean/C-Star/pull/886>`_)

  - Compressing outside a scheduler job on a cluster warns that login nodes may stop the process; ``CSTAR_ALLOW_LOGIN_NODE_RUN=1`` silences the warning.

- Oscar (Brown CCV) is a registered system: C-Star loads its modules, builds with the site's gcc and ``hpcx-mpi``, and submits jobs with ``cstar blueprint submit`` and ``cstar workplan submit``. (`#887 <https://github.com/CWorthy-ocean/C-Star/pull/887>`_)

  - Jobs go to the ``batch`` partition by default (``debug`` is also known) and launch with ``srun --mpi=pmix``; no ``CSTAR_SLURM_ACCOUNT`` is needed unless you use a condo or priority account.
  - The machine is recognised by its ``/oscar/home`` mount; ``cstar env set CSTAR_SYSTEM oscar`` pins it if detection misses.
  - With no ``SCRATCH`` variable exported, ``CSTAR_DATA_HOME`` resolves onto the user's ``~/scratch`` directory.

- ``ts_output.wrt_avg_temp`` and ``ts_output.wrt_avg_salt`` write temperature and salinity to the averages file (ucla-roms 0.14.0); the wizard shows them under "Variables in average files". (`#896 <https://github.com/CWorthy-ocean/C-Star/pull/896>`_)

  - Both are off by default and take effect only with ``ocean_vars.wrt_file_avg``.

- New bundled ModelSpec ``roms-marbl-0.14-default`` for ucla-roms 0.14.0. (`#896 <https://github.com/CWorthy-ocean/C-Star/pull/896>`_)
- The wizard's surface forcing rows have blend controls (fallback source, its radiation correction, blend width and profile); choosing CONUS404 offers ERA5 as the fallback and moves the row's radiation correction to it. (`#901 <https://github.com/CWorthy-ocean/C-Star/pull/901>`_)
- A physics surface forcing item accepts a ``blend`` block that fills every grid point a regional source misses from a global one such as ERA5, using ROMS-Tools' surface-forcing blend. (`#901 <https://github.com/CWorthy-ocean/C-Star/pull/901>`_)

  - ``fallback`` takes its own ``source``, ``correct_radiation`` and ``options``; ``width_km`` (``0``, the default, switches at the footprint's edge) and ``profile`` (``smoothstep`` or ``linear``) shape the band between the two.
  - When any surface item has a blend, every surface item must set the same ``coarse_grid_mode``, ``never`` or ``always``.
  - Forge writes one blended file, ``<name>_surface-physics-<primary>-<fallback>_*.nc``.

- Forge accepts CONUS404, the 4 km North American reanalysis, as a physics surface forcing source (``source: {name: CONUS404}``), streamed from its store on Amazon S3. (`#901 <https://github.com/CWorthy-ocean/C-Star/pull/901>`_)

  - The files kept always include the record just before the run's start and the one just after its end, so ROMS reads the same records as before. The log names how many files of each kind each run uses.
  - A forcing list longer than the model reads (360 files before ucla-roms 0.13.0, 64 for the GPU model) is no longer refused when each run's own window needs fewer files.

- A ucla_roms run whose forcing does not reach back to its start or on to its end is refused before ROMS is built; before, ROMS stopped at its first step ("First available forcing record is past current time") or at its last step ("Ran out of time records"), after the queue wait and the run. (`#938 <https://github.com/CWorthy-ocean/C-Star/pull/938>`_)

  - The error names each forcing variable that falls short, the files that hold it, the time span they cover and the span the run needs.
  - Carbonate sensitivities the build does not read from files, and river forcing with rivers off, are not checked; any other forcing file the build does not read is, so remove such a file from the blueprint.

- ``cstar blueprint check`` and ``cstar forge run`` refuse, before any input is generated, a Forge settings section switched on that the pinned ucla-roms release lacks, such as ``implicit_fs.fs_mode: implicit`` before 0.15.0, and the wizard's settings check lists it; before, the build step stopped with a traceback. (`#950 <https://github.com/CWorthy-ocean/C-Star/pull/950>`_)
- The Forge wizard's model dropdown hides ``roms-marbl-0.9-default``, ``roms-marbl-0.10-default`` and ``roms-marbl-0.11-default`` unless "Show archived" is checked; blueprints that name them keep working. (`#951 <https://github.com/CWorthy-ocean/C-Star/pull/951>`_)
